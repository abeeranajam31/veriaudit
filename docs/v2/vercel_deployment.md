# Vercel deployment: fixing "No Next.js version detected"

Checked 2026-11-13. No dashboard settings were changed; this note is for the project owner.

## Cause

The Next.js app lives in `frontend/` (its `package.json` declares `next` 16.3.4). The Vercel
project's **Root Directory** is the repository root, which has no `package.json`, so Vercel cannot
detect Next.js. The repo-root `vercel.json` (`cd frontend && …`) worked for the last successful
deploy on 2026-09-15 but no longer passes framework detection. The `veriaudit-x-dataset` branch does
not touch `vercel.json` or any `package.json`; `main` has the same configuration, so the next
production deploy from `main` will most likely fail the same way.

Locally, `next build` on this branch compiles, type-checks and prerenders all 16 routes.

## Required setting

| Setting (Project → Settings → Build and Deployment) | Value |
|---|---|
| Root Directory | `frontend` |
| Framework Preset | Next.js |
| Build Command | default (override **off**) — runs `npm run build` = `next build` |
| Output Directory | default (override **off**) — `.next` |
| Install Command | default (override **off**) |
| Include files outside the root directory in the Build Step | not needed (the app imports nothing outside `frontend/`) |
| Node.js Version | 20.x or newer (Next 16.3.4 requires Node ≥ 20.9.0) |

If any of Build, Output or Install shows an override copied from `vercel.json` (for example
`cd frontend && npm run build` or `frontend/.next`), switch the override off. Those paths are wrong
once the root is `frontend/`.

## What stays valid

- **Environment variables:** the frontend reads none (`grep process.env frontend/src` finds
  nothing). `NEXT_PUBLIC_API_URL` in `.env.example` is documented but unused. Variables already set
  in the dashboard are project-scoped and are unaffected by the Root Directory.
- **Data:** the `/results` page reads `frontend/src/data/v2/dashboard.json`, which is inside
  `frontend/`. It is regenerated by `research/platform/export_dashboard_data.py` and must be
  committed.
- **Repo-root `vercel.json`:** Vercel reads `vercel.json` from the Root Directory, so after the change
  this file is ignored. It can be deleted in a later commit on `main`; it is left in place for now so
  the change stays in the dashboard only.

## Steps

1. Vercel → project **veriaudit** → Settings → Build and Deployment.
2. Set Root Directory to `frontend` and save.
3. Make sure the Build, Output and Install overrides are off and Node.js is 20.x or newer.
4. Deployments → the failed `veriaudit-x-dataset` preview → Redeploy.
5. If it succeeds, the same setting applies to production on the next deploy from `main`.
